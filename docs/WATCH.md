# Живой дашборд флота (`watch`)

`watch` — режим только для чтения: раз в `--interval` миллисекунд собирает состояние флота и
перерисовывает кадр в терминале. В отличие от TUI он не принимает клавиш и не требует raw mode,
поэтому одинаково работает в Termux, по SSH и в обычном окне Windows.

```sh
node Program.js watch
node Program.js watch --once
node Program.js watch --json
```

## Что читается

| Источник | Обязателен | Назначение |
| --- | --- | --- |
| `fleet-status.json` | нет | снимок состояния от `lib/Fleet.js`: `states`, `bots`, `updatedAt`, `clubTag`, `creationPaused`, `metrics` |
| `fleet.pid` | нет | проверка, что флот действительно запущен (PID + `/proc/<pid>/cmdline`, если доступен) |
| `fleet.log` | нет | последние строки вывода фонового процесса |
| `accounts/index.json` | нет | необязательный реестр аккаунтов; имена и теги подставляются ботам без своих значений |
| `.runtime/results/*.json` | нет | ошибки последних команд флота |

Отсутствие любого файла — не ошибка. Если `fleet-status.json` нет, дашборд пишет
`fleet-status.json отсутствует — флот ещё не запускался`; если процессов нет —
`флот не запущен` и подсказку, как запустить. Битый JSON показывается как
`fleet-status.json повреждён: <ошибка>`, а не роняет дашборд.

В живом цикле тяжёлые чтения кэшируются: `fleet.log` перечитывается только при смене размера
или `mtime`, а каталог `.runtime/results` — не чаще раза в 2.5 с (разбираются 20 самых свежих
файлов). Поэтому `--interval 100` не читает лог и десятки JSON на каждый кадр.

## Флаги

| Флаг | По умолчанию | Поведение |
| --- | --- | --- |
| `--interval <мс>` | `1000` | период перерисовки; значения меньше `100` поднимаются до `1000` |
| `--once` | выкл. | один кадр и выход |
| `--json` | выкл. | один кадр объектом в stdout, без перерисовки; равносильно `--once` |
| `--log-lines <n>` | `8` | сколько последних строк `fleet.log` показать; `0` — скрыть блок |
| `--bots <first:count>` | все | фильтр по индексам, например `--bots 1:13` |
| `--no-color` | выкл. | без ANSI-цветов; также отключается через `NO_COLOR` или когда stdout не TTY |

Флаги можно ставить в любом порядке: `--once --json` и `--json --once` дают один и тот же
один JSON-кадр. `--once` — булев флаг без значения, следующий аргумент он не съедает.

`tools/watch.js` запускается и напрямую (`node tools/watch.js --once`): разбор флагов общий,
через `lib/Args.js`, глобальные `--json`/`--quiet`/`--no-color` снимаются до общего разбора.

`Ctrl+C` завершает дашборд чисто: таймер снимается, курсор возвращается, код выхода `0`.

## Что показывает

1. Заголовок с временем кадра и строку состояния флота: `запущен (PID N)` или `не запущен`.
2. Время последнего обновления статуса и возраст снимка (`4 с назад`, `3 мин назад`).
3. Сводку состояний (`online: 5, queued: 3, failed: 2`), строку `онлайн X из Y`, среднее время
   входа и RTT, тег клуба, флаг паузы создания ботов и число аккаунтов в реестре.
4. Таблицу ботов: номер, тег, имя, статус, число попыток, текст ошибки. Ширины подстраиваются
   под терминал, длинные значения обрезаются с `…`; CJK-символы считаются за две ячейки.
5. Последние строки `fleet.log`.
6. Ошибки последних команд из `.runtime/results`: сообщение и время файла результата.

## Как читать метрики

Блок метрик появляется, только если данные есть; иначе в значении стоит `—`.

- `вход` — среднее время от старта подключения до подтверждённого входа, мс. Источник:
  `metrics.avgLoginMs` (или `metrics.loginMs`), иначе среднее по полю `loginMs` ботов.
- `RTT` — средняя задержка сервера, мс. Источник: `metrics.avgRttMs` (или `metrics.rttMs`),
  иначе среднее по полю `rttMs` ботов.

Поля `metrics` необязательны: `lib/Fleet.js` может их не писать, и дашборд это переживает.
Возраст снимка больше нескольких секунд означает, что флот занят или не успевает писать статус
(статус пишется не чаще двух раз в секунду и раз в 30 секунд heartbeat-ом).

## Ограничения

- Только чтение: команды флоту отправляются через `tools/fleet.js`, а не из дашборда.
- Перерисовка по таймеру, а не по событию: свежесть кадра равна `--interval`.
- Требуется терминал фиксированной ширины; при ресайзе кадр подстроится на следующем тике.
- В `--json` нет истории: это один снимок, а не поток.
- `/proc` есть не на всех платформах; без него живость процесса проверяется только `kill(pid, 0)`.

## Примеры

Termux (узкий экран, без цветов, кадр раз в 2 секунды):

```sh
node Program.js watch --interval 2000 --log-lines 5 --no-color
node Program.js watch --once --bots 1:5
```

Windows PowerShell (один снимок в файл для разбора):

```powershell
node Program.js watch --json | Out-File -Encoding utf8 fleet-snapshot.json
node Program.js watch --once --interval 500
```

## `--json` и `--quiet` (глобальные флаги)

Оба флага работают с любой командой, включая `watch`.

`--json` — машинный вывод. В stdout попадает ровно один JSON-объект, без баннеров, подсказок и
человеческих строк:

```json
{ "ok": true, "result": { "version": "0.3.1", "host": "…" } }
```

Ошибка печатается в stderr как `{"ok":false,"error":{"message":"…","code":"…"}}` и даёт код выхода
`1`; неподтверждённое сервером действие (`confirmed: false`) даёт код `2` и `error.code =
"unconfirmed"`. Поддерживается `--json=false`, поэтому флаг можно отключить в обёртке.
`Debugger` и предупреждения клиента при этом идут в stderr и не загрязняют stdout.

`--quiet` — подавляет всё, кроме итогового результата: подсказки, предупреждения
`client.on('warning')` и строки `Debugger` (он становится no-op). Ошибки по-прежнему уходят в
stderr. Флаги не конфликтуют: `node Program.js lang --quiet --json` вернёт тот же объект.

Оба флага вынимаются из `argv` до `lib/Args.js`, поэтому не съедают следующий аргумент и не ломают
внешние скрипты; `--no-color` обрабатывается там же.
