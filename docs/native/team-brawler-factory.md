# Выбор бойца в лобби: разбор нативного клиента (libg.so, Nulls 69.252)

Источник: `lib/arm64-v8a/libg.so` из base.apk, vaddr == файловое смещение для первого
PT_LOAD (r-x, 0x0..0x11a5410). Дизассемблер: capstone 5.0.7 (`mov w0, #imm` + `ret` = type getter).
Все адреса ниже — vaddr.

## Как искались классы

Каждый класс сообщения содержит пару геттеров подряд: `mov w0,#<id>; ret` и `mov w0,#<version>; ret`.
Сквозной скан первого сегмента на `movz w0, #imm` дал по одному совпадению на id — это и есть
type getter. encode/decode — функции непосредственно перед парой геттеров.

## Как выглядит выбор бойца на сервере (для сверки)

`24124` (входящий, decode 0xf38820) создаёт объект команды 0x90 байт и вызывает `0xf33024`
(разбор команды). Участник — объект 0x110 байт: encoder `0xf37c54`, decoder `0xf37fa4`,
конструктор нулей `0xf37bf8`. Порядок полей участника: bool[0x00], long[0x08] (tag),
DataRef[0x10], DataRef[0x18], VInt[0x20], [0x24], [0x28], [0x2c], [0x30], [0x34], bool[0x01],
[0x38], [0x3c], [0x40], [0x44], [0x48], [0x4c], [0x50], вложенный объект[0x58] (`0xf3e394`),
DataRef[0x60], [0x68], [0x70], [0x78], [0x80], [0x88], [0x90], DataRef[0xa8], [0xb0], VInt[0xb8],
VInt[0xa4] + массив DataRef[0x98], VInt[0xd8], VInt[0xdc], VInt[0xec] + массив int32[0xe0],
VInt[0xfc] + массив int32[0xf0], VInt[0x100], DataRef[0x108], DataRef[0xc0], [0xc8], [0xd0].
`lib/Decode.js` (`teamMember`) читает первые два DataRef как `brawler` и `skin`; живая фикстура
подтверждает `members[0].brawler.class === 16` (tests/session-fleet.test.js:115). Значит боец в
состоянии команды — DataReference класса 16.

## Кандидаты на «смену бойца в лобби» и что подтверждено

**Кандидат A — 14375 (0x3827, ver 23), encode 0xf35ba8, decode 0xf35bdc.**
Поля: int32[0x90] = индекс слота, int32[0x94] = id бойца (глобальный числовой id, не DataRef).
Подтверждено: единственная точка отправки — `0x9c38b4/0x9c38c0` внутри функции `0x9c3864`,
которая вызывается как колбэк выбора бойца (`0x9cce98`: `ldp x8,x1,[x0,#8]; mov x0,x8; b 0x9c3864`).
Там `w1 = [x19,#0xc4]` (индекс слота), `w2 = 0xe037a0(0xdf1b28(x20))` — id выбранного бойца из
объекта-бойца; после отправки локально пишется `[x21+0x2f0][slot] = hero` и вызывается
виртуальный метод `[x19+8]->[0x1d0]`. Ветка при отрицательном индексе (`tbnz w8,#0x1f`) показывает
попап с подписью кнопки «Equip» (строка 0x1f0f3a), т.е. это тот же экран выбора/экипировки.
Логика именно «слот → боец», id бойца числом — как в 14369 (там боец тоже VInt[0xa4]).

**Кандидат B — 14354 (0x3812, ver 9), encode 0xf35de0, decode 0xf35e5c, vtable 0x1226aa0.**
Конструкторы: 0xf35c8c (по умолчанию), 0xf35ccc(ref, ref, int), 0xf35d2c(ref, int), 0xf35d80(ref, ref, int).
Поля: DataRef[0x90], VInt[0x98], DataRef[0xa0], DataRef[0xa8], DataRef[0xb0], VInt[0xc0], VInt[0xc4], DataRef[0xb8].
Подтверждено: отправляется из экранов экипировки/лоадаута — `0x93169c` и `0x9b7e4c`
(`ctor 0xf35d2c(msg, heroObject, slot)`, затем локально `[x21+0x2f0][slot] = hero`,
перед этим ветка с ошибкой `TID_ITEM_DISABLED_CURRENTLY`), `0xbf2d80` (заполнено только первое поле,
остальное null/0 — «сменить только бойца»), `0xc8a424` и `0x97246c`/`0x9724f8` (полный лоадаут:
ref + skin/star power/gadget/gear). Это согласуется с записью в PROTOCOL-MAP.md, что 14354 —
сообщение экипировки, а не выбора бойца в лобби.

**Не подтверждено (не выдавать за факт):**
- что именно 14375, а не 14354, меняет `members[own].brawler` в 24124 — живой проверки не было;
- что индекс слота в 14375 — это позиция участника в команде (0..2), а не индекс слота
  ранкед-пика/бота; рядом стоит 14373 (0x3825: int32 слот + bool) — конфигурация бота в слоте;
- какой класс DataReference соответствует бойцу в *исходящих* сообщениях этого блока:
  в 14354 первый DataRef при отправке из экипировки получает объект бойца напрямую,
  и класс 16 там живой проверкой не подтверждался (PROTOCOL-MAP фиксирует отказ);
- семантика 14360/14361/14362/14364/14366/14368/14370/14371/14374 — восстановлена только
  раскладка полей, обработчики не разбирались;
- 14102/14104/14105/14107/14110 — геттеры найдены, encode/decode и поля целенаправленно не сверялись.
