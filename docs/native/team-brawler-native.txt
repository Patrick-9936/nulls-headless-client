## Живая проверка (21.11.2026, Nulls 69.252, brawl.server.dnull.xyz:9339)

Лобби из двух гостевых аккаунтов (`create-room --type 0` + `join-room`), 24124 приходит
обоим, у участника боец — DataReference класса 16, скин — класса 29.

Отправка 8 байт `slot(int32 BE) | id(int32 BE)`, id = 16000000 + index:

| проба | ответ сервера |
|---|---|
| slot 0, id 16000005, v23 (лидер) | нет ответа 20 с, соединение живо |
| slot 1, id 16000006, v23 (второй участник) | нет ответа |
| slot 0, id 16000000, v23 (значение без изменений) | нет ответа |
| тот же payload, v23 / v9 / v0 | нет ответа |
| 145 id: 0–20 и 16000000–16000123, slot 1, 8 байт | ни одного 24124, TeamData не меняется |
| 5 байт `00 85 90 a1 0f`, v23 | соединение закрыто через ~0.3 с |

Контроль в той же сессии: `team-status` → 24124 за ~2 мс; сырой 14355 (ready bool=1) при
одинаковых бойцах → 24129 `00 11 00 00` (VInt 0, код 17, пустая строка) за ~270 мс.
14354 с 9 VInt (`16,6,0,0,0,0,0,0,0`) → обрыв соединения; 14352 (`16 05`) → тишина.

Вывод: сервер разбирает 14375 как два int32 (короткий payload валит соединение), но
применения нет — TeamData после отправки не меняется и ответ не приходит. Раскладка
подтверждена, семантика на сервере — нет. Числовой id 16000000+index на проводе не
наблюдается: TeamData отдаёт только `16:index`, поэтому соответствие остаётся
реконструкцией по каталогу клиента.
