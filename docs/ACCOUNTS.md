# Реестр аккаунтов (Accounts)

`lib/Accounts.js` и `tools/accounts.js` — слой только для чтения/индексации поверх `accounts/*.json`.
Реестр ничего не создаёт и не логинит: сетевых операций в нём нет вообще.

## Зачем реестр

`accounts/bot-N.json` — источник истины. Флот и CLI читают эти файлы напрямую, а реестр — производный
индекс, который избавляет инструменты от полного скана каталога на каждый запрос:

- быстрый `list`/`show`/`stats` без чтения всех файлов;
- одна точка правды для тегов, ников и клубов;
- устойчивость к битым файлам: один повреждённый JSON не ломает обзор остальных.

Индекс можно удалить в любой момент — он пересоберётся сам.

## Каталог и формат

| Путь | Назначение |
| --- | --- |
| `accounts/bot-N.json` | аккаунт бота с индексом `N` (источник истины) |
| `accounts/index.json` | производный реестр, кэш, режим `0600` |

```json
{
  "version": 1,
  "updatedAt": "2026-11-21T12:00:00.000Z",
  "accounts": [
    {
      "file": "bot-1.json",
      "index": 1,
      "hi": 0,
      "lo": 123456,
      "tag": "#ABC123",
      "name": "Bot1",
      "club": "#CLUB01",
      "team": null,
      "hasToken": true,
      "bindToken": false,
      "updatedAt": "2026-11-21T11:59:00.000Z",
      "size": 412
    }
  ]
}
```

- `file` — имя файла внутри `accounts/`, без абсолютных путей: реестр переносим вместе с каталогом.
- `index` — из имени `bot-N.json`; для остальных `*.json` — `null`. Такие файлы всё равно попадают в скан.
- `hi`/`lo` — LogicLong из аккаунта, `tag` — `logicLongToTag`, `null` если тега ещё нет.
- `club` — тег клуба строкой (если в файле лежит разобранный объект, берётся `.tag`), иначе `null`.
- `team` — как в файле (объект или `null`).
- `hasToken` — есть ли `passToken`; `bindToken` — есть ли `bindToken`. **Значения токенов в реестр не попадают.**
- `updatedAt`/`size` — mtime и размер файла аккаунта.
- битый JSON даёт запись с дополнительным полем `error`; скан при этом не прерывается.

Сортировка: по `index`, записи без индекса — в конце, затем по имени файла.

## Когда пересобирается

- `read()` отдаёт индекс, если он не старше 60 с и число `*.json` в `accounts/` совпадает с числом
  записей. Иначе индекс пересобирается целиком (`refresh`).
- `refresh()` всегда делает полный скан и пишет `index.json` атомарно (`lib/Store.js`: временный файл,
  `rename`, режим `0600`).
- Флот не пересобирает реестр на каждый вход: `upsert()` обновляет одну запись поверх уже
  загруженного индекса (без `readdir`/скана `accounts/*.json`) и планирует запись файла не чаще
  одного раза в 5 секунд. Отложенная запись объединена с таймером `unref()`.
- Полный скан (`refresh`) выполняется только из `read()`, если индекс отсутствует, старше 60 с
  или разошёлся с числом файлов, а также по явной команде `accounts refresh`.
- При остановке флота (`SIGTERM`/`SIGINT`) выполняется финальный синхронный flush отложенной
  записи: последние ники/теги/клуб не теряются.
- Если запись `index.json` не удалась, накопленные изменения остаются в памяти и повторяются
  при следующей записи, а не пропадают.
- Ошибка реестра не влияет на флот: она логируется один раз через `Debugger.warn`.

## CLI

```sh
node tools/accounts.js list                 # таблица
node tools/accounts.js list --json          # полный JSON реестра
node tools/accounts.js list --registered    # только passToken + hi/lo
node tools/accounts.js list --limit 20
node tools/accounts.js show 3               # по индексу
node tools/accounts.js show '#ABC123'       # по тегу
node tools/accounts.js show Bot1            # по точному нику
node tools/accounts.js refresh
node tools/accounts.js prune --dry-run
node tools/accounts.js prune
node tools/accounts.js stats
node tools/accounts.js cleanup
```

Все команды печатают JSON в stdout (кроме табличного `list`), сеть не используется, код возврата `1`
только при ошибке команды или ненайденном аккаунте.

`stats` возвращает `{total, withToken, withClub, broken}`.

## Prune: что удаляется

`prune` удаляет **только** то, что восстановить невозможно или нечего восстанавливать:

- `*.json`, в которых нет `passToken`, нет `bindToken` и нет `hi`/`lo` — пустая заготовка;
- осиротевшие `*.lock` (блокировка аккаунта) и `*.tmp-*` (временный файл `Store.write`), если
  соответствующего файла аккаунта больше нет.

Никогда не удаляются:

- файлы с `passToken` — даже если в них нет `hi`/`lo`;
- файлы с `bindToken`;
- битые JSON (они попадают в `skipped` с причиной `unreadable`, чтобы файл можно было восстановить);
- `index.json` и любые файлы вне шаблонов `*.lock` / `*.tmp-*`.

`--dry-run` строит тот же отчёт (`removed`, `skipped`, `errors`), но ничего не удаляет.

## Восстановление реестра

```sh
rm accounts/index.json      # или ничего не удалять
node tools/accounts.js refresh
```

`refresh` перечитывает каталог и пишет индекс заново. Если реестр разошёлся с файлами (ручное
копирование, удаление), достаточно любого `read` — расхождение числа файлов вызовет пересборку.

## Токены и приватность

`passToken`, `bindToken`, `deviceId` и подобные поля лежат в `accounts/bot-N.json`. Эти файлы —
учётные данные: с ними можно войти в аккаунт. Поэтому:

- `accounts/` в `.gitignore`; не коммитьте и не прикладывайте к issue;
- реестр (`index.json`) хранит только флаги `hasToken`/`bindToken`, а не значения;
- `tools/accounts.js show` не печатает токены;
- режим файлов — `0600` через `lib/Store.js`/`utils/Platform.js#fileModeSecure` (на Windows режим
  игнорируется, доступ регулируется ACL);
- при утечке файла аккаунт нужно пересоздать/перепривязать — токен нельзя «отозвать» правкой реестра.

## Очистка `.runtime`

`cleanup(root, options)` живёт в `lib/Accounts.js`, потому что это единственный модуль состояния,
который грузится и CLI реестра, и флотом, без `Client`/`Actions`/`Messaging`. Функция:

- удаляет `.runtime/results/*.json` старше 1 часа (`resultsMaxAge`);
- удаляет зависшие `.runtime/commands/*.processing` старше 10 минут (`processingMaxAge`);
- удаляет `*.tmp-*`/`*.lock` в `.runtime` старше суток (`staleMaxAge`).

Не трогаются: `accounts/`, `working-proxies.json`, `config.json`, `client-license.bin`, `connect.json`
и любые файлы вне `.runtime`. `tools/accounts.js cleanup` печатает отчёт; в `fleet run` та же функция
вызывается при старте и далее раз в 10 минут (`unref()`).
