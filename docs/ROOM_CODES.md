# Код комнаты и серверный ID

Нативный клиент использует алфавит `QWERTYUPASDFGHJKLZCVBNM23456789` (31 символ). Значение `(lo << 8) | hi` записывается в системе счисления 31, перед ним добавляется `X`. Обратно: `hi = value & 255`, `lo = value >> 8`. Рабочая реализация — utils/TeamCode.js, утилита — `node Program.js room-code X5AMWKM`.

Пример: `X5AMWKM` ⇔ hi=0, lo=2939074. Это обратимое представление ID, а не генератор новых комнат.

В ранее записанной серии двенадцати собственных комнат, созданных последовательно на одном TCP-соединении, lo были: 2939074, 26875, 2884777, 2847567, 933386, 9444, 2886618, 2716485, 158392, 1438244, 2350999, 455346. Порядок не монотонный. Наблюдения совместимы со случайным или переставленным распределением; конкретный серверный алгоритм и состояние генератора неизвестны. Один код не позволяет установить предыдущую или следующую созданную комнату.

`--offset 1` кодирует численно соседний lo, но не означает следующую комнату и не проверяет её существование. Клиент не перебирает чужие комнаты.

Теги игроков и клубов — отдельный алфавит `0289PYLQGRJCUV`, основание 14, то же упакованное значение `(lo << 8) | hi`. Зная ID можно вычислить его тег. Наличие корректного тега не доказывает существование игрока/клуба. Получить реальные теги можно из ответа рейтинга, друзей и состава клуба. Рейтинг не является выгрузкой всех аккаунтов сервера. Полный список всех комнат, клубов или игроков в исследованном протоколе не найден.
