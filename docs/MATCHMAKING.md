# Прогресс подбора и разделение ботов

Сервер присылает прогресс конкретного подбора в пакете 20405. `matchmaking.found` — найденные игроки, `matchmaking.required` — требуемое количество, `matchmaking.progress` — строка вроде `1/6` или `9/10`. Вместимость берётся из ответа, фиксированного максимума 6 в клиенте нет. Это не число всех игроков в общей очереди сервера. `updatedAt` показывает время последнего ответа; после разрыва соединения счётчик может устареть. При загрузке боя или подтверждённой отмене прогресс сбрасывается.

Просмотр:

```sh
node tools/candidates.js status
node tools/fleet.js status
```

В `candidates` по умолчанию `--max-queued 1`: следующий бот начинает подготовку и подбор после того, как сервер назначил матч предыдущему (20559/24112) или подтвердил отмену (20406). Уже назначенные матчи могут идти одновременно. Количество зарегистрированных аккаунтов и темп их создания регулируются отдельно.

```sh
node tools/candidates.js start --initial 10 --max 10 --max-queued 1 --minutes 60 --name 'nbtest' --battle-transport udp
```

Новый запуск использует сохранённые аккаунты. Если нужен процесс проверки прокси, такой же параметр поддерживает `tools/test-session.js start --max-queued 1` с остальными параметрами из CODESPACES.md.

Ожидающие боты отображаются в `matchmakingWaiting` и `bots[].waitingForMatchmaking`, занятые слоты — в `matchmakingReserved`. Утрата TCP-соединения и таймаут после отправки Ready не освобождают слот: сервер мог сохранить подбор. После повторного входа нужен ответ о загрузке или отмене; один Home не подтверждает выход из очереди. Ошибка до отправки Ready освобождает слот.

Этот режим координирует один процесс `candidates`. Ручные команды `fleet`, другие процессы и восстановленные старые серверные очереди не получают общей блокировки. При восстановлении уже идущих подборов новые запросы ждут их завершения. Клиент уменьшает вероятность совместного попадания своих ботов, но состав матча определяет сервер: абсолютная гарантия требует ограничения на стороне сервера, в том числе для пополнения уже назначенных матчей.

## Основание декодирования

Nulls v69.252: native encoder 20405 по адресу `0xf49ea8` записывает пять int32 BE и boolean. Обработчик `0xa7bffc` переносит поля сообщения `+0x94/+0x98` в UI `+0x204/+0x208`. Код `0xa7b06c` подставляет их в `TID_MATCHMAKING_PLAYERS` как `<x>` и `<y>`. Фрагменты: [native/20405-progress-ui.txt](native/20405-progress-ui.txt). Сохранённый ответ длиной 21 байт содержит `[0,1,6,0,0]` и false; он используется как тест. Значение остальных полей сохранено в `fields` без предположений об их назначении.

Сериализация очереди проверена локальным тестом шести одновременных ботов, включая разрыв, восстановление, пустой пакет загрузки и подтверждённую отмену. Новый массовый тест на сервере не запускался.
