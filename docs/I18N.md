# Локализация (i18n)

Интерфейс клиента (CLI, TUI, сообщения об ошибках) переведён на каталоги локализации.
Поддерживаются `ru`, `en`, `tr`, `zh`; по умолчанию — `ru`, чтобы поведение клиента
не менялось для существующих скриптов.

## Где что лежит

| Файл | Назначение |
| --- | --- |
| `lib/i18n.js` | загрузка каталогов, `resolve`, `t`, выбор языка, кэш |
| `lib/locales/<lang>.json` | плоские каталоги: ключ с точками → строка |
| `tools/i18n-check.js` | валидатор каталогов (CI) |
| `tests/i18n.test.js` | тесты `resolve`/`t`/приоритета/CLI |

Каталоги плоские: никаких вложенных объектов.

```json
{
  "cli.help.commands": "Команды: {commands}",
  "tui.action.ready": "нажать «готово»"
}
```

`{name}` — плейсхолдеры, подставляются из второго аргумента `t(key, params)`.
Если ключа нет в текущем каталоге, поиск идёт `текущий → en → ru → сам ключ`.
Неизвестный ключ `t()` возвращает как есть — интерфейс не падает из-за опечатки.

## Как выбрать язык

Приоритет (первое найденное значение побеждает):

1. `--lang <code>` у любой команды: `node Program.js help --lang tr`;
2. `config.json` → `uiLanguage`;
3. переменные окружения `NULLS_LANG`, затем `LC_ALL`, `LC_MESSAGES`, `LANG`
   (понимаются теги вида `ru_RU.UTF-8`, `tr-TR`);
4. `ru`.

`node Program.js lang` печатает текущий язык и список поддерживаемых.
`node Program.js lang tr` проверяет код, сохраняет `uiLanguage` в `config.json`
и печатает подтверждение на выбранном языке. Неизвестный код — ошибка со списком
поддерживаемых и код выхода `1`.

В TUI переключение доступно пунктом «язык интерфейса» в главном меню и в разделе
«инструкция и утилиты». Выбор сразу применяется к подписям и сохраняется в `config.json`.

## Как добавить язык

1. Скопируйте `lib/locales/en.json` в `lib/locales/<code>.json` и переведите значения.
   Ключи, плейсхолдеры и их набор менять нельзя.
2. Добавьте код в `SUPPORTED` в `lib/i18n.js` и название в `NAMES` (например
   `de: 'Deutsch'`). `DEFAULT` не меняйте без отдельного решения — это меняет
   поведение существующих установок.
3. Прогоните валидатор:

   ```sh
   node tools/i18n-check.js
   ```

   Он сверяет наборы ключей с `ru.json`, пустые значения и наборы `{...}`-плейсхолдеров,
   печатает расхождения списком и завершается с кодом `1` — пригоден для CI.
4. Прогоните тесты: `node --test tests/i18n.test.js` и `npm test`.
5. При необходимости добавьте язык в примеры `cli.help.lang` во всех каталогах.

## Что влияет на сеть, а что нет

Смена языка интерфейса — это только отображение. Она **не** меняет параметры логина
и не переключает `loginLayout`.

В `config.json` есть три разных ключа:

- `locale` (`ru-RU`) — значение локали, которое уходит в **legacy**-раскладку логина
  (единственное поле локали в этой раскладке);
- `preferredLanguage` (`en`) — используется только **modern**-раскладкой логина,
  вместе с `storefrontCountryCode` и `storefrontId`; значение не менялось, чтобы
  не трогать существующую конфигурацию (поле сейчас ни на что не влияет, пока
  `loginLayout` = `legacy`);
- `uiLanguage` (`ru`) — язык интерфейса CLI/TUI, на протокол не влияет.

`loginLayout` остаётся `legacy` (см. issue #3). Modern-раскладка добавляет поля,
которые legacy-сервер не ожидает; включать её «вслепую» при смене языка нельзя —
это меняет структуру логина и может ломать вход. Если modern-логин понадобится,
это отдельное решение с проверкой на живом сервере, а не побочный эффект перевода.

## Известные ограничения

- Рекомендации клубов, ранжирование, названия клубов и прочий серверный контент
  приходят с сервера и от языка интерфейса не зависят.
- Смена `uiLanguage` на `tr` не делает контент турецким: переводятся только
  подписи клиента; серверные рекомендации и регионы остаются как есть.
- Документация в `docs/*.md` и `README.md` не переводятся автоматически.
- Однофайловый бандл `Nulls.js` собирается отдельно; после правок каталогов его
  нужно пересобрать, иначе в бандле останется старая копия.
