# Проверка выпуска 0.3.1

21 ноября 2026. 0.3.1 — это 0.3.0 плюс авто-выбор языка интерфейса, управление TUI в
vim-стиле и точная раскладка `LoginOk` 69.252. Ниже: что подтверждено на живом
сервере в 0.3.0–0.3.1, затем история проверок предыдущих выпусков.

## 0.3.0–0.3.1, 21 ноября 2026

Живая проверка на `brawl.server.dnull.xyz`, Nulls 69.252: `ClientHello` →
`ServerHello` → `Login` v10 → `LoginOk`, затем Home и список друзей; новый гость
подтверждён сервером. С блоком лицензии 723 байта (из установленного APK) сервер
отвечает `LoginFailed error=8`; вход проходит с блоком 595 байт из PR #1, он и
входит в выпуск.

`LoginOk` 69.252 снят с живого сервера дважды и разобран раскладкой `nulls-69`:
плоские 32-битные id и строки, bind-token Nulls Connect лежит в zlib-потоке в конце
пакета, `pid` в claims совпадает с `accountId.lo`. Живой вход сохраняет `bindToken`
в аккаунт. Обезличенные фикстуры — `tests/fixtures/login-ok-69.bin` и
`tests/fixtures/login-ok-69-no-token.bin`; их читает `tests/login-ok.test.js`, токенов
аккаунтов в них нет.

`npm test` — 168 из 168, `npm run check` — без ошибок, `npm run lint` (eslint) —
0 ошибок, `node Nulls.js --self-test` — ok, 362 файла в бандле.

Регион аккаунта пере-проверен 21 ноября на одноразовых гостях: `create-account
--region KE` и `account-region --region US`. Запрос 12998 несёт DataReference
14:index (VInt класс + VInt индекс), ответ 24178 — VInt код + DataReference
(для 14:125 живой ответ `00 0e bd 01`). После кода 0 и переподключения страна в
HomeData сменилась RU→KE и KZ→US. `LoginOk.countryCode` при этом остался `RU`
(страна по IP), поэтому подтверждение в клиенте строится на Home, а не на LoginOk.
Разбор страны — `lib/HomeRegion.js`; тесты — `tests/account-region.test.js`.
В 0.3.3 пара «страна + хост» читается по якорю внутри Home (смещение от якоря
фиксированное, абсолютное плавает), скан остаётся фолбэком; живые фрагменты —
`tests/fixtures/home-region-live-*.bin`, тесты — `tests/home-region.test.js`.

С внешним владельцем возвращается `confirmed: false` с пояснением: сервер присылает подтверждение владельцу, а не отклонившему игроку.

## Ограничения

- Изменение уже заданного ника: запрос 10212 native version 9, ответ 20205 с кодом 0. Смена имени и повторный вход не подтверждены; команда rename недоступна. Имя выбирается при регистрации.
- Выбор бойца: 14354 оказался выбором экипировки; ссылка класса 16 приводила к отключению. Неверная отправка заблокирована. Поэтому обычная команда из одинаковых бойцов не может стартовать; клиент сообщает причину до отправки ready.
- Приглашение соклубника без дружбы отдельно проверено: получено 24589, принято через 14479, оба клиента подтвердили общее лобби. Отмена приглашения подтверждена удалением pendingInvite.
- После принятия/отклонения повторное приглашение тестового получателя сервер иногда отвергал ошибкой 27. Клиент показывает отказ; не обходит ограничение.
- Заявки в клуб с текстом, одобрение/отказ и лобби с отменой/одобрением/отказом проверены. Исправлены ID записи клубной заявки и порядок ID запроса в лобби. Подтверждение исходящих заявок в лобби наблюдается у владельца, нужен второй бот того же fleet.
- Остальные экспериментальные команды перечислены в COMMANDS.md и features.json, требуют --experimental и не обещают подтверждения результата.
- UDP: подключение через SOCKS5, получение VisionUpdate с растущим тиком, BattleEnd и следующий подбор проверены на отдельном аккаунте. Движение и атаки отсутствуют; управление персонажем не объявляется реализованным.
- Возраст, Supercell ID, автоматическая совместимость с произвольными будущими major не подтверждены.
- Удержание онлайн тестировалось тремя собственными ботами; долговременный круглосуточный прогон и 80 сессий в этом выпуске не выполнялись.
