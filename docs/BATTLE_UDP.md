# UDP-подключение к бою

В 0.2.3 добавлен UDP-канал Nulls v69.252: разбор подключения из 24112, 10-байтовый идентификатор сессии, входящие VisionUpdate 24109 и нейтральные ClientInput 10555. Подключение считается установленным после корректного кадра именно этой сессии, а не после создания сокета или отправки первого пакета. Проверено на живом обычном матче: серверные тики росли, затем получен BattleEnd и начат следующий подбор.

```sh
node tools/candidates.js start --initial 1 --max 1 --name 'МойБот' --battle-transport udp --minutes 30
node tools/candidates.js status
node tools/candidates.js stop
```

Режим включается явно: `--battle-transport udp`. Этот параметр поддерживают одиночный CLI, fleet, candidates и test-session. Для candidates с прокси добавьте `--proxy-pool working-proxies.json`; для одиночного CLI и fleet — `--proxy-pool-file working-proxies.json`. Без настроенного прокси используется прямой UDP.

Для прокси нужен SOCKS5 с поддержкой UDP ASSOCIATE. Рабочий TCP CONNECT не подтверждает поддержку UDP; HTTP CONNECT не переносит этот канал. При использовании пула клиент проверяет несколько SOCKS5-прокси, сохраняя TCP-сессию аккаунта. Подтверждённые UDP-прокси хранятся отдельно в `.runtime/udp-proxies.json`. Общие настройки сети устройства не меняются.

В статусе candidates поле `udp` содержит `state`, число отправленных пакетов `sent`, принятых `received`, корректных кадров `visionUpdates`, последний серверный тик `serverTick` и время `lastVisionAt`. `active` означает получение кадра боя. Фаза цикла `battle` появляется после кадра текущей сессии. `inputAck: -1` не трактуется как подтверждение команд управления.

Клиент посылает нейтральные пакеты с подтверждением полученных кадров. Движение, атаки, выбор целей и автоматическое прохождение боя ещё не реализованы. Получение VisionUpdate не доказывает, что бот двигался, наносил урон или выиграл матч. Завершение засчитывается только по серверному BattleEndMessage, после которого выполняется новый подбор.

При отсутствии кадров 10 секунд UDP-сессия закрывается и проверяется новое подключение. UDP закрывается также при завершении боя, отключении аккаунта и остановке процесса. Повреждённые пакеты, чужие идентификаторы сессии и фрагментированные SOCKS5-датаграммы отклоняются. Шифрованные параметры UDP из другой версии протокола явно отклоняются; текущие проверенные подключения передавали пустые параметры шифрования.

Формат игры восстановлен из предоставленной native-библиотеки, функции 0xf84db0, 0xae8538, 0xae88a0, 0xf28534, 0xf499a4 и 0xf4b4b4. Сокеты используют [Node.js dgram](https://nodejs.org/api/dgram.html), прокси — [SOCKS5 UDP по RFC 1928](https://www.rfc-editor.org/rfc/rfc1928#section-7). Токены аккаунта и идентификаторы UDP-сессий в архив не включены.
