# Заявки, регион и встроенные боты

Проверено на настоящем сервере Nulls 69.252 8 октября 2026. Команды для работающих ботов отправляйте через fleet. Теги заменяйте своими; новые аккаунты создаются автоматически при старте fleet с `--name-prefix`.

## Клуб по заявкам

Бот 1 должен быть президентом/иметь право принимать участников. Бот 2 должен находиться вне клуба.

```sh
node tools/fleet.js command --bot 1 --action club-settings --type 2
node tools/fleet.js command --bot 2 --action club-request --club-tag '#КЛУБ' --text 'Хочу вступить'
node tools/fleet.js command --bot 1 --action club-requests
node tools/fleet.js command --bot 1 --action club-answer --tag '#БОТ2' --accept=false
```

Для одобрения другой ожидающей заявки используйте `--accept=true`. Можно ответить через `--entry-id 0:ID_ЗАПИСИ`. Клиент сам находит ID записи по тегу; отправлять тег игрока вместо ID заявки было ошибкой и исправлено. Текст обязателен. Состояния записи: 1 ожидает, 2 одобрена, 3 отклонена. При одобрении дополнительно проверяется свежий состав клуба.

Отправка подтверждается ответом 24333 с кодом 50. Если владелец — другой онлайн-бот этого fleet, клиент также проверяет текст в его ленте (`textVerified: true`). Код 52 означает уже существующую заявку; клиент не выдаёт новый текст за применённый. `club-stream` читает серверную ленту текущей сессии, `--refresh` переподключается для получения свежей истории. Разобраны типы записей 2/3/4/6/8; неизвестный тип даёт ошибку, не пустой успешный список.

## Заявки и приглашения в лобби

```sh
node tools/fleet.js command --bot 1 --action create-room --type 0
node tools/fleet.js command --bot 2 --action team-request --code XКОД --tag '#БОТ1'
node tools/fleet.js command --bot 1 --action team-info
node tools/fleet.js command --bot 2 --action team-cancel-request
```

Чтобы ответить, сначала отправьте новую заявку:

```sh
node tools/fleet.js command --bot 1 --action team-request-answer --tag '#БОТ2' --accept=true
```

`--accept=false` отклоняет заявку. В `team-info` есть `requests`, `pendingInvites`, участники и их `status`. Порядок ID исправлен: сначала владелец, затем команда. Появление и отмена заявки подтверждаются на стороне владельца. Для `confirmed: true` при отправке/отмене нужен владелец в том же fleet; внешнему владельцу пакет отправляется с `confirmed: false` и пояснением.

```sh
node tools/fleet.js command --bot 1 --action team-invite --tag '#ДРУГ_ИЛИ_СОКЛУБНИК'
node tools/fleet.js command --bot 2 --action accept-invite
node tools/fleet.js command --bot 2 --action leave-room
```

Проверено приглашение соклубника без дружбы. Для отмены ещё не принятого приглашения отправитель использует `team-cancel-invite --tag '#TAG'`. Для отказа получатель использует `decline-invite`. Внутри одного fleet клиент дожидается доставки приглашения получателю, чтобы следующая команда принятия не выполнялась раньше входящего пакета. Сервер может отказать: например, код 25 для заполненной команды, 27 для игрока, который не принимает приглашения.

## Регион и эмблема

```sh
node Program.js regions
node Program.js club-badges
node tools/fleet.js command --bot 1 --action account-region --region US
node tools/fleet.js command --bot 1 --action club-settings --region 14:125 --badge 8:1
```

`account-region` принимает код страны (`US`, `KZ`), `DisplayName`, индекс или `14:N`; ждёт 24178/0 и ту же ссылку класса 14, затем переподключается и сверяет страну в Home (`countryVerified`, `homeCountry`). Проверены US (14:249), KZ (14:125) и KE (14:126) на живом сервере. `LoginOk.countryCode` — страна по IP, после смены остаётся `RU`; это не страна аккаунта. `create-account --region` применяет регион сам после подтверждения ника. Это выбор страны профиля, не прокси и не смена сетевого сервера. Эмблема клуба проверяется по свежему ответу 24301, страна клуба — по ссылке или возвращённому коду страны. Изменение описания не сбрасывает прочитанную страну клуба.

### Страна в HomeData

В Home (24101/24180) страна и хост лежат одной парой: `u32 2`, две буквы страны, `u32` длина хоста, ASCII-хост. Это не отдельный `int32` с кодом, а две строки с 32-битной длиной; `LoginOk.countryCode` к этой паре отношения не имеет.

Пара стоит сразу за 16-байтовым якорем `00 00 00 00 00 00 00 90 06 7f 00 00 00 01 10 00`. В живых Home 69.252 якорь уникален. Абсолютное смещение пары плавает: 1632 в обычном Home (RU/KZ/US, ник `CapOne` и `AVeryLongName14`) и 1630 в Home без подтверждённого ника; от якоря смещение всегда 16 байт. Поэтому `lib/HomeRegion.js` сначала ищет якорь и читает пару по нему, проверяя границы, две заглавные латинские буквы, длину хоста 3..255, точку и ASCII без пробелов. Если якоря нет или пара не сходится — работает прежний побайтовый скан, но с теми же проверками и лимитом 64 кандидата. Результат — `{country, host, offset, method: 'anchor'|'scan'}`.

Живые обезличенные фрагменты — `tests/fixtures/home-region-live-kz.bin` и `tests/fixtures/home-region-live-us.bin` (только участок с якорем и парой, без тегов и токенов). Тесты — `tests/home-region.test.js`. Полная раскладка Home и смысл самого якоря в native-коде пока не разобраны; для 24180 остаётся фолбэк-скан.

## Событие, статус и встроенные боты

```sh
node tools/fleet.js command --bot 1 --action team-status --status 2
node tools/fleet.js command --bot 1 --action create-room --type 1
node tools/fleet.js command --bot 1 --action team-bot --slot 1 --disabled=true
node tools/fleet.js command --bot 1 --action team-bot --slot 1 --disabled=false
```

Статус подтверждается в поле своего участника. Номера статусов не снабжены непроверенными названиями. Встроенные боты доступны в дружеском лобби; выключенный слот появляется в `disabledSlots`, включённый исчезает.

`team-event --event ID --slot N --modifier 0` выбирает серверное событие в обычной команде. Проверена смена 10248817/1 → 20248817/2 с изменением карты и вместимости. Эти ID относятся к ротации дня проверки: не используйте их как постоянный каталог. ID события отличается от индекса карты; полный каталог событий Home ещё не разобран.

## Пока экспериментально

`club-invite`, `team-advertise`, `practice`, `player-status`, старый `team-answer` требуют `--experimental`. Первые четыре проверены отправкой, но нужного серверного результата не получено. `player-status` проверяет присутствие через онлайн-друга того же fleet; это отдельная команда от работающей `team-status`. Реклама команды и тренировочный бой не объявлены работающими. Для старого `team-answer` используйте проверенные `accept-invite`/`decline-invite`.

## Nulls Connect

Привязка игровых аккаунтов к e-mail через Nulls Connect вынесена в отдельный CLI. Полный цикл, хранение токена и типовые ошибки — `docs/CONNECT.md`.

```sh
node tools/connect.js pin --email user@example.com
node tools/connect.js confirm --email user@example.com --pin 1234
node tools/connect.js bind --account accounts/bot-1.json
node tools/connect.js links
```

## Выбор бойца в лобби

Пакет 14375 (`0x3827`, version 23) — единственный клиентский пакет смены бойца в лобби:
libg encode `0xf35ba8`, decode `0xf35bdc`, getter `0xf35c14`; поля по порядку —
`int32` слота участника (`+0x90`) и `int32` числового id бойца (`+0x94`), writer
`0x5b7334` = `writeInt32` (big-endian). Отправляется из `0x9c3864` колбэком выбора
бойца `0x9cce98`, после отправки клиент локально пишет `team[+0x2f0][slot] = hero`.
14354 — это лоадаут/экипировка (8 полей), к лобби не относится; 14103/14113 в клиенте
отсутствуют, 14114 пустой, 14115 — long+long+VInt.

```sh
node Program.js team-brawler --account accounts/bot-1.json --experimental --brawler Gunslinger --slot 0
node Program.js team-brawler --account accounts/bot-1.json --experimental --brawler 16000005   # = 16:5
```

Живые пробы (bot-1, `create-room --type 0`, пакет 14375 v23, payload `00000000 00f42405`):
сервер не ответил ни ошибкой, ни обновлением 24124, и не разорвал соединение. Более ранние
кандидаты отклонены: 14354 (`1001` + 7 нулей, v9), 14357 (v23), 14364 (v23), 14369 (v23) —
обрыв соединения, иногда с предварительным 24131; 14359 (несуществующий пакет) — 24131 без обрыва.
Поэтому команда помечена `experimental`: формат восстановлен, но результат в лобби живьём
не подтверждён. Подтверждение в `Actions` берётся из TeamData (24124): выбранный боец
сверяется с `brawler` своего участника, иначе команда сообщает, что сервер выбор не подтвердил.

### Проверка в активном лобби из двух аккаунтов (21.11.2026)

Схема: аккаунт A `create-room --type 0` (коды `XMGSBKJ`, `XJB93AA`, `XKYU44L`, `XAYAD34`),
аккаунт B входит `join-room --code`, оба видят друг друга в 24124 (`members: 2`, `type: 0`,
`maxMembers: 3`). Пакеты слались и через `Actions`, и сырым `messaging.send` с точным payload.

- **TeamData (24124)** отдаёт бойца участника как `DataReference` класса 16 (у нового гостя
  `{class:16,index:0}`), скин — класс 29. Числового id бойца в TeamData нет, только ссылка.
- **14375 от лидера (slot 0, id 16000005, v23)**: за 20 с не пришло ничего — ни 24124, ни
  24129, ни 24131; соединение живо (следом `team-status` штатно получил 24124).
- **14375 от второго участника (slot 1, id 16000006)** и **от лидера с slot 1**: тишина.
- **14375 с id 16000000** (значение, которое уже стоит в TeamData): тишина.
- **Версии 23 / 9 / 0** для одного и того же 8-байтового payload: тишина.
- **Перебор**: 145 отправок 8-байтового payload с id `0–20` и `16000000–16000123` от второго
  участника — ни одного 24124, в TeamData у обоих остался `16:0`.
- **Контроль в той же сессии**: `team-status` → 24124 за ~2 мс; сырой `14355` (ready) при
  одинаковых бойцах → **24129** с payload `00110000` (первый VInt 0, код 0x11 = 17,
  пустая строка) за ~270 мс — это `data/team-errors.json[17]`
  «Cannot start game. Duplicate Brawlers are not allowed.» Сервер жив и отвечает на соседние пакеты.
- **Короткий payload 14375** (5 байт, `00 85 90 a1 0f`) рвёт соединение через ~0.3 с, а
  8-байтовый — нет. Похоже, сервер разбирает ровно два int32 и падает на нехватке байт:
  обработчик 14375 у него есть, но состояние команды он не меняет и ответ не шлёт.
- **14354** (лоадаут, 9 VInt `16,6,0×7`, v9) — обрыв соединения; **14352** (`16,5`, v23) — тишина.

Итог: раскладка 14375 подтверждена (8 байт, два `int32` big-endian; короткий payload сервер
не переваривает), но применение выбора на сервере Nulls 69.252 не подтверждено — ни один
пакет не изменил `brawler` в 24124. Правило `16000000 + index` остаётся реконструкцией по
каталогу клиента: TeamData даёт только `16:index`, числовой id на проводе сервер не отражает.
Негативный случай (одинаковые бойцы) сервер закрывает кодом 17 в 24129 — это единственный
подтверждённый живьём ответ по теме выбора бойца.
